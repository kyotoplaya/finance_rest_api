## 1. Архитектура и кто за что отвечает

| Файл          | Роль                                                                 |
|---------------|----------------------------------------------------------------------|
| `main.py`     | Точка входа: `create_all()`, `seed()`, подключение роутеров          |
| `database.py` | Движок, фабрика сессий, `Base`, `get_db()`, включение FK-проверки    |

| `helpers.py`  | Общие функции: расчёт баланса, дельты, проверка минимума             |
| `seed.py`     | Системная категория «Корректировка» при старте                       |

Правило: **схема != модель**. Модель — строка в БД. Схема — то, что летит по HTTP. Они похожи, но это разные вещи.

## 2. Паттерн схем (самая повторяемая штука в FastAPI)

На каждую сущность — линейка из 4 схем:

```python
class XBase(BaseModel):          # общие поля
    ...

class XCreate(XBase):            # поля, нужные при создании
    pass

class XUpdate(XBase):            # все поля опциональны (для PATCH)
    field: str | None = None

class X(XBase):                  # то, что уходит клиенту
    id: int
    model_config = ConfigDict(from_attributes=True)
```

- `from_attributes=True` — схема умеет строиться из ORM-объекта.
- Для PUT (полная замена) берут `XCreate`, для PATCH (частичное изменение) — `XUpdate` с `| None`.

## 3. Дизайн-решения, которые мы приняли (и почему)

**Тип транзакции берётся из категории, а не из отдельного поля.**
У транзакции нет `transaction_type`. Есть `category_id` → тип доход/расход/корректировка. Это убивает два зайца: не может быть «расход по категории-доходу» и не надо хранить дублирующийся тип.

**Сумма всегда положительная.**
`income` прибавляет, `expense` вычитает, `adjustment` — со своим знаком (`±`). Направление движения определяет категория, а не минус в сумме.

**Баланс вычисляется, а не хранится.**
`balance = initial_balance + Σ вкладов транзакций`. В БД лежит только `initial_balance`. Считать нечего пересчитывать — хранить дубликат баланса это всегда источник рассинхрона.

**Системная категория «Корректировка».**
- Одна, создаётся сидом, `is_system=True`.
- Клиент МОЖЕТ её использовать в транзакциях (экспенс-корректировки).
- Клиент НЕ может создать/удалить/изменить её (403).
- Клиент не может создавать свои `adjustment`-категории.

**Безопасность данных:**
- Сумма `0` запрещена (400).
- Баланс не может уйти в минус (400 «Insufficient funds»).
- `ON DELETE RESTRICT` на FK + `PRAGMA foreign_keys=ON` в SQLite + явная проверка в коде с понятным 409.

**Деньги — только `Decimal`, никогда `Float`.** `0.1 + 0.2 = 0.30000000000000004`, для бухгалтерии смертельно.

## 4. Грабли, за которые задели

### 4.1 `db.query(...).filter(...)` НЕ выполняет запрос
Он возвращает объект `Query` — «рецепт». Результат появляется только после `.first()` / `.all()`. Поэтому:

```python
x = db.query(X).filter(X.id == id).first()   # x может быть None
```

Без `.first()` проверка `if x is None` никогда не сработает.

### 4.2 Порядок проверок: сначала `None`, потом атрибуты
Удаляем непойми что:

```python
if x is None:                        # СНАЧАЛА существует ли
    raise HTTPException(404, ...)
if x.is_system:                      # ПОТОМ читаем поле
    raise HTTPException(403, ...)
```

`None.is_system` → `AttributeError` → 500.

### 4.3 `create_all` НЕ изменяет существующие таблицы
Поменял модель — старые таблицы не обновятся. Надо удалить `db/finance.db` и пересоздать (для пет-проекта; в бою — миграции, это отдельная тема).

### 4.4 `computed_field` в схеме не имеет доступа к БД
Схема не знает про сессию. Поэтому баланс считаем в роутере (`compute_balance`) и кладём в атрибут объекта перед возвратом. Схема просто объявляет `balance: Decimal`.

### 4.5 Поле-сирота без значения вернёт дефолт
`Account.balance` с дефолтом `0` вернёт `0`, если не присвоить. **Каждый endpoint, возвращающий сущность с вычисляемым полем, обязан его заполнить.**

### 4.6 Вредный оптимизм в проверках
```
if transaction is None: raise 409   # НАОБОРОТ! Ошибку кидаем на «плохом» случае
if transaction is not None: raise 409   # так: «есть транзакция → нельзя удалить»
```

Формула: **проверка-страховка возвращает ошибку на "плохом" случае.**

### 4.7 Порядок исполнения кода в файле имеет значение
`@event.listens_for(engine, ...)` до `engine = create_engine(...)` → `NameError`. Декораторы выполняются в момент чтения строки.

### 4.8 Поле, затеняющее тип: `date: date`
`date: date | None` падает — имя поля конфликтует с типом. Решение: `import datetime` и `datetime.date | None`, либо `Optional[date]`.

### 4.9 `with_entities` / выбор колонок при join
Чтобы вытащить не всю модель, а пару полей из двух таблиц:

```python
db.query(CategoryModel.category_type, TransactionModel.amount)
  .join(CategoryModel, TransactionModel.category_id == CategoryModel.id)
  .filter(TransactionModel.account_id == account.id)
  .all()
```

## 5. HTTP-статусы, которые мы используем

| Статус | Когда |
|--------|-------|
| 200    | ОК / список / объект                                    |
| 201    | Создано (`POST`)                                        |
| 400    | Невалидные данные по правилам приложения (сумма 0, не хватит средств) |
| 403    | Запрещено правилами доступа (системная категория)       |
| 404    | Не найдено (сущности / ссылки нет)                      |
| 409    | Конфликт с состоянием (категорию с транзакциями не удалить) |
| 422    | Автоматическая валидация Pydantic (типы, обязательные)  |

## 6. Денежная арифметика: знак дельты

```python
def transaction_delta(category_type, amount):
    return -amount if category_type == CategoryType.EXPENSE else amount
```

Вклад транзакции в баланс **всегда со знаком**. При апдейте транзакции:

1. убрать вклад старой (вычесть СТАРУЮ знаковую дельту),
2. прикинуть новую дельту,
3. проверить, что баланс не уйдёт в минус.

`balance = compute_balance(db, account) - old_delta; ensure_balance_not_negative(balance, new_delta)`

## 7. Рабочий ритуал

1. `import main` — проверить, что всё импортируется.
2. `uvicorn main:app --reload` + `/docs` — протестировать вручную.
3. Внёс изменение схемы БД → удали `db/finance.db`, пересоздай.
4. Проверь `git status` и `git diff` перед коммитом.
5. Коммит — по-русски, глагол+суть (Реализован / Добавлен / Починен / Переведён).

`.gitignore` хранит: `.venv/`, `__pycache__/`, `db/*.db`, `git-github.json`. Секреты в git не попадают.
